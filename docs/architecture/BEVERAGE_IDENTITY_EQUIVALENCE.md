## Review artifact contract

`beverage-identity-packet-v1` contains `policy_sha256`, random `blind_id`, `created_utc`, a `rubric` copied exactly from the policy's identity_requirement/equivalences/failures/review_rule/reviewer_kind fields, and `cases`. Each case has a random `case_id`, `image_sha256`, absolute `photo_path`, `reference` with brand/product only, and `prediction` with outcome/brand/product only. No structured predicted/reference capacity fields, run kind, checkpoint, scores, target percentage or model metadata appears in reviewer-visible text. Identity text is preserved rather than rewriting product names. Reviewers inspect the photo itself, which naturally includes its printed quantity. A separate mapping binds that packet to the experiment.

`beverage-identity-packet-map-v1` contains `policy_sha256`, `manifest_sha256`, `split_policy_sha256`, `predictions_sha256`, `run_metadata_sha256`, `inference_split`, `created_utc`, relative `packet_path`, `packet_sha256`, and exact `cases` mappings of case_id/image_id/image_sha256. One packet covers every selected split case, including missing/failed outputs. Output directories are exclusive; paths, source bytes and packet hashes are checked. Test packet creation requires the complete existing test-inference provenance checks. Validation packets are development only.

Each `beverage-identity-review-v1` file has distinct `reviewer_id`, `reviewer_kind: codex_agent`, `independence_attestation: independent_blind_packet_only`, `packet_sha256`, `policy_sha256`, `reviewed_utc` (after packet creation), and exactly one judgment per packet `case_id`. Judgments contain `verdict` (full_identity_equivalent, meaningful_identity_error, uncertain), nonempty `reason`, and `photo_inspected: true`. Reviewers must not inspect other packets, run outputs, test assets beyond their assigned packet, or one another's work. Both independent equivalent verdicts are required. Missing, duplicate, foreign, uninspected, unbound or inconsistent reviews are rejected. Source prediction validation and exact-volume correctness come from the existing deterministic scorer, never the reviewer. All missing/failed predictions remain failures in the denominator.

Final `beverage-equivalence-evaluation-v1` reports require the original full test evidence plus both bound reviews and this policy. The frozen selection must contain `identity_policy_sha256`, and the policy timestamp must precede test inference. Baseline or synthetic fixtures cannot satisfy the adapter target. Reports retain legacy lexical metrics, conservative identity/joint metrics, exact-volume results, confidence intervals/strata, agreement and source/review hashes. Hash consistency does not itself authenticate reviewer independence or factual visual judgments; those are supported by the recorded isolated review tasks and remain an explicit limitation.
