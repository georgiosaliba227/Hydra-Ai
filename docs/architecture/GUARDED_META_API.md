One PROJECT-WIDE first-test permit is immutable, account-bound, metadata-normalized-JPEG-SHA256-bound, explicitly reviewed by both developers and authorized by the selected account owner and spending authority, expiring, capped at $0.25 and consumed atomically BEFORE dispatch. Missing account attestation, pricing evidence, notices delivery, maximum-cost bound, key, consent or permit denies dispatch. Any unresolved attempt in either account denies another request. The real transport supports only HTTPS api.meta.ai /v1/responses, no redirects, proxies, tools, Files API, history, background calls or SAM. One bounded JPEG; 512 output tokens including reasoning; strict compact JSON schema (display titles omitted, constraints retained); minimal reasoning effort; no model nutrition. Provider usage is derived only from the authenticated transport response, never HTTP-client figures. Usage settlement precedes recognition parsing, so billed malformed/refused/incomplete responses remain accounted. Missing/invalid usage freezes further dispatch. Unverified manual reconciliation evidence is recorded but cannot release money.

IMPORTANT: current official transport uses the conservative shared-context bound (1,048,576 total context positions minus 512 reserved output tokens = 1,048,064 maximum input tokens). At reviewed Standard prices plus 512 output tokens this is $1.312256 before any additional charges, exceeding $0.25. Under the active $0.25 first-test policy, dispatch therefore remains BLOCKED even with keys/flags/approvals. A smaller documented/enforced token-cost bound needs independent verification and code review; do not replace it with a guessed image-token estimate or caller-supplied count. Test transports use synthetic bounds and NEVER send to Meta.

GET /v1/recognition-capabilities reports configured mode and privacy terms; never claims readiness guarantees. GET /v1/meta/notices exposes durable sanitized per-recipient notices. Backend errors remain sanitized/retryable=false for live attempts. Live response mode=meta_live, recognition_id=attempt UUID; confirmed logs pass recognition_id and server checks a successful settled receipt before assigning Meta provenance. Original mock/manual payload fingerprints remain compatible.

Consent explicitly covers disclosure to Meta, whose retention terms are not zero retention. Redraw/resize on device; no location/HealthKit export. No image/prompt bytes persist in the ledger or logs. Price/model/account/approval/dispatch/usage metadata and UTC audit events do persist. GitHub notification delivery is server-side, fixed repository, outbox-based, and requires its own credential; tests inject a fake sender. Delivery receipts are persisted separately for each developer; no assumed delivery from creating an event.

Live payload normalization strips all JPEG APP/EXIF/XMP/IPTC/comment segments, including between progressive scans. Permit hashes bind the resulting metadata-free bytes actually sent. The private admin tool's `image-fingerprint --image` computes that hash locally; it makes no network call. Structure is bounded/checked without entropy decoding; image-owner review and the iOS redraw remain important.

## Integration review: project-wide holds and invoice finality

An account frozen after anomalous usage blocks admission and dispatch for the whole project, including previously approved permits on the other account. Recheck inside each admission/send transaction. Usage settlement does not establish invoice finality.

Before any subsequent controlled approval or request, every prior attempt must have an immutable `live_finalities` record. The private operator import binds attempt UUID, selected account, provider response ID, exact final gross micro-USD, past UTC finalization time, provider evidence reference and both developer review references; `provider_finality_verified` must be explicitly true. Import is allowed only for an already usage-settled, nonfrozen attempt whose account, provider ID and final cost exactly match the existing record. It cannot release unresolved reservations, change amounts, unfreeze accounts or bypass another hold. Unknown costs, discrepancies and nonzero-extra-charge recovery remain blocked pending separately reviewed reconciliation work.

This import records reviewed human attestations to authenticated provider evidence; it does not authenticate an invoice itself. Synthetic tests may exercise it in temporary ledgers. The permanent private ledger is not migrated or populated by this integration review. Missing finality schema/evidence fails closed. A human must separately review any future schema initialization against the authoritative ledger; no copied active ledger is permitted.
