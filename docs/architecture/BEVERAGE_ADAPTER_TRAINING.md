# Beverage image adapter experiment

Owner assignment, November 2, 2026: collect approximately250 beverage images in varied real settings/backgrounds and train recognition of drink identity and volume, targeting measured success above70%. The owner selected actual open-Meta-model adapter training rather than calling prompt tuning weight training.

## Training and evaluation contract

Use an open Meta Muse Glimmer30B checkpoint in4-bit MLX form, pinning model and runtime revisions. Train low-rank language adapters with the image encoder/base weights frozen. Run on the owner's M4Pro24GB Mac; first verify a bounded forward/backward/update/save/reload cycle fits. No paid GPU or new hosted subscription is authorized. The existing Spark phone backend remains unchanged until this experiment has measured results. The local runner uses the pinned official MLX runtime plus the tracked `separate-frozen-vision-v1` patch described below: vision-only feature preparation exits before language-only execution. Record the exact patch SHA, actual execution policy and executable SHA in selected inference configuration and run evidence. This does not change pretrained weights or raise OS memory limits.

Collect about250 unique licensed source photos, not generated backgrounds counted as real settings. Record sourceURL, sourceproduct/barcode, author, license, originalhash, processedhash, printed-capacity evidence, brand/product aliases (including preregistered brand_aliases for visible brand abbreviations) and reviewed background class. Exclude duplicate/near-duplicate views across splits. Group connected source-product IDs, near-duplicate groups and shared normalized full-identity aliases together, including the same visibly identifiable product under different barcodes or sizes. Source metadata is reference evidence, not guaranteed ground truth: check identity and printed quantity against the photo before admitting it. Separate studio/plain from natural backgrounds and report each stratum. Preregister at least100 natural-background photos overall, at least30 in the test split, and at least3 distinct reviewed natural test settings; a studio-only dataset cannot satisfy the request. Review `drink_family` using water/soda/juice/sports/energy/milk/plant_milk/tea/coffee/beer/wine/other. Require at least6 families with at least10 images each, no family over75 images, and at least5 test families with at least5 images each; many brands of one drink type cannot replace beverage diversity.

Volume means printed container capacity normalized to integer mL, not remaining liquid or consumption. Prefer the printed metric declaration over a fluid-ounce conversion; when printed metric mL is fractional, normalize with Decimal ROUND_HALF_UP to the nearest whole mL (502.8mL→503), retaining the literal decimal in capacity_evidence. Scoring requires the exact normalized integer, not a percentage tolerance. Visible label truth must be transcribed/verified independently of predictions. Serving quantity and multipack totals are not individual container capacity. An unreadable/unsupported quantity stays unknown; unknown capacity is not a successful positive volume prediction.

Freeze splits before training:150train,25validation,75test, adjusted only for indivisible product groups while preserving approximately250 total. Fit/choose adapters and decoding only on train/validation. Final test is scored after checkpoint selection; do not tune to it. If another iteration follows a failed final test, preserve its result and obtain fresh held-out examples rather than repeatedly optimizing against the same test.

Primary success requires BOTH correct top1 drink identity (brand plus product/type/flavor as visibly identifiable, under preregistered aliases) AND exact printed capacity mL on each eligible test case. Report identity, capacity, joint success, abstentions, errors, background strata, counts and95%Wilson intervals separately. Target is strictly>70% observed joint test success; do not claim population accuracy from a small sample or replace the metric with category-only accuracy. An easier proxy or synthetic replay cannot satisfy this goal.

Images/weights stay outside Git. Commit reproducible collection, validation, splitting, training, inference and scoring tools plus aggregate reports/manifests with attribution; no personal camera/HealthKit history is included. Inputs to the model contain pixels and the fixed recognition instruction only, never filenames, barcode metadata or ground-truth answers. Real updated adapter weights and before/after held-out predictions must exist before claiming training or success.

## Separate frozen-vision execution (November 2 runtime addendum)

Repeated direct-pixel validation caused severe paging during the third language prefill despite releasing vision and staying within sampled guards. Preserve those partial validation artifacts as development results; they cannot satisfy final evaluation. Run frozen vision and language in separate sequential processes so their weights never coexist. Keep model weights, dataset, reference aliases, success metric, financial/privacy controls, memory guards and OS settings unchanged.

Add a versioned local feature cache produced by the pinned Meta vision encoder from unannotated pixels and the fixed prompt only. Its descriptor must bind each original processed image SHA, split/ID, feature tensor path/SHA/dtype/shape, prompt/template/processor/tokenizer settings and exact base-model/encoder-runtime provenance. Cached text tokens contain only the fixed prompt/header and image placeholders; no reference brand, product, capacity, filenames or barcode metadata enters model input. Paths and tensor hashes must be validated before consumption. Cache files remain outside Git.

The vision worker must load only frozen vision weights and tokenizer/processor data, not language weights. The language worker must load only language weights and validated frozen features, never silently reload vision or call a hosted provider. The cached-feature path must match direct-pixel conditioning in a meaningful tiny paired forward/update/reload test. Actual separate-process memory, updates and saved/reloaded tensors must also be measured on the pinned real checkpoint before full training is accepted. The trained adapter still updates actual last-layer q/v tensors; feature extraction alone is not training.

Prepare train and validation caches separately using label-free projections. Never give test images or their feature tensors to training or validation model workers. Parent integrity checks may hash the full frozen cohort without interpreting test pixels or feeding them to a model. Test-cache creation starts only after checkpoint/configuration selection is frozen. Encoder settings/policy belong to the selected inference-config hash; split-specific cache manifests and their actual use are separately bound in each run's evidence, so validation and test may contain different images under the same selected pipeline. The final evaluator must verify those bindings and actual execution policy.

The first separate-process real preflight passed with identical loss to the historical direct run and exact save/reload agreement, but pageable GPU buffers still caused severe system paging. Use the SDK process-local residency ticket capped at the minimum of 16GiB, the existing MLX budget and Apple’s device recommendation. This pins only this process’s existing GPU buffers; it does not increase OS/device limits or allocate that budget eagerly. Restore the ticket on normal/error exit. Keep sampled MLX/RSS guards. Actual runtime evidence records the requested residency budget and executable SHA; verify the resulting hardware throughput before accepting sustained training.
