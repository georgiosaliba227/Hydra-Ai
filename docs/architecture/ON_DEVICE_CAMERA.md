# Offline iPhone camera MVP — 2026-11-04

The owner selected an entirely on-iPhone camera and authorized a focused 2–4 hour implementation on November 4. The accepted scope is a small Meta beverage-category model, local label reading, existing Confirm/Edit and durable local saving. This records that scope and implementation choices; it is not a general accuracy or physiological-volume claim.

Use Meta DINOv2 Small as a frozen image feature extractor and train a small category head on the existing reviewed public beverage cohort, retaining its product-separated train/validation/test splits. Export a fixed 224×224 Core ML model with bundled weights. Training/conversion dependencies are isolated development tools (PyTorch, Transformers, Pillow, NumPy and coremltools); none become backend or iPhone package dependencies. Pin source revision, hashes, preprocessing, labels, training parameters, and measured validation/test results. The 30B adapter is a separate model and is not transferred or represented as the phone model.

Approaches considered: this specialized Meta classifier plus Apple Vision OCR keeps core image inference Meta-based and avoids a generative runtime; a small general vision-language model adds conversion/runtime risk and requires an exception to the Meta-only architecture. The owner accepted the specialized MVP. Latency, memory and recognition quality must be measured, not promised.

The iPhone performs both Core ML inference and Apple Vision OCR locally, with no network client in the recognition service. Offer explicit On this iPhone recognition alongside the existing server path. No automatic server fallback, retries, credential use, downloads at runtime, or financial-ledger changes. Require camera/photo permission and an explicit Analyze action; do not show backend/Meta upload consent for on-device inference.

Suggest category from the trained head conservatively. Names/brands may use readable label text and deterministic catalog matches; unknown names/categories stay editable. Only unambiguous printed container capacity in mL, L or US fl oz can prefill size. Reject serving-only, multipack, conflicting and implausible declarations. Capacity never measures remaining liquid or actual consumption. Automatically open the existing finished-drink Confirm/Edit review; preserve explicit whole-container/entire-liquid assumptions, units, user corrections, original suggestion and model version.

On-device confirmations use a separate protected local store, with explicit source and original suggestion provenance, stable idempotency, restart persistence, export/deletion and a deterministic beverage-volume total. Exclude real local records and on-device pending writes from backups, retaining protection/exclusion across atomic replacements. Read persisted dates structurally so a clock rollback cannot hide the history; new submissions retain future-time admission checks. Edit offers an independent optional container size, clearable to unknown, separately from the amount to log; preserve the original photo size and confirmed corrections distinctly. Preserve existing backend settings/history and legacy offline demo records. Real camera records must never be written as synthetic mock examples. No automatic migration, upload, training-photo storage or training; existing server correction/training paths retain their separate controls. Personal corrections for this MVP are local saved entries; automatic correction reuse is deferred.

Verification covers parser ambiguities, model shape/identity and conversion parity, missing model, stale camera tasks, failed inference without fallback, request destination binding, local idempotency/restart/export/delete and assumption provenance. Run complete pytest and relevant XCTest, simulator UI and signed device builds. Physical install/airplane-mode confirmation depends on a reachable unlocked phone; simulator verification is reported separately. This cohort lacks robust non-beverage negatives and natural-glass coverage; category scores are uncalibrated and broad recognition is not established.
