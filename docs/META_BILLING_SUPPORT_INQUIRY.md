## Public verification record — 2026-10-27

The following public documentation was independently reread without authentication or provider requests:

Hydra's one-image, 1 MiB/2048-axis limits are stricter local limits.
- [Responses](https://dev.meta.ai/docs/protocols/responses) requires input plus requested output to fit the shared context. [Reasoning](https://dev.meta.ai/docs/reasoning) includes reasoning in billed output and the output cap; `minimal` is supported and `none` is not. The selected 512-token limit covers reasoning and visible text together.
- [Pricing](https://dev.meta.ai/docs/pricing-rate-limits) lists Standard input at $1.25/M, cached input at $0.15/M, and output at $4.25/M, with no long-context premium. No cache discount is assumed. Therefore `(1,048,576 - 512) * 1.25 / 1,000,000 + 512 * 4.25 / 1,000,000 = $1.312256`; the proposed $2 ceiling leaves $0.687744 for every independently bounded additional charge. This is a conservative single-pass token calculation, not a quote or verified whole-request bill.
- [Token counting](https://dev.meta.ai/docs/token-counting) distinguishes rendered context from billing, warns of cumulative usage across hosted-tool iterations, and says fixed image estimates are not portable. Its billing warning conflicts with the image guide's cost-estimation language. No counting call is authorized or needed for the conservative context calculation.
- [Spend alerts](https://dev.meta.ai/help/billing/spend-limit-alert) do not enforce a usage ceiling. [Terms](https://dev.meta.ai/legal/terms-of-service) describe account service rates, applicable taxes, expiring credits, possible internal model invocation, and a separate invoice-billing spending limit. Those statements do not establish a $2 all-inclusive bound for this account/request. Standard's no-training policy does not alone prove zero retention.
